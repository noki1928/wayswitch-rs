# wayswitch-rs

Автоисправление русско-английской раскладки — порт
[WaySwitch](https://github.com/Wetoshkin/WaySwitch) на Rust с упором на защиту
паролей. `ghbdtn␣` → `привет␣`; двойной Shift исправляет последнее слово, тройной —
фразу, двойной сразу после автоисправления отменяет его.

> **Статус: ранняя версия. Проверялась только в X11: KDE Plasma, MX Linux, один
> компьютер. На Wayland не запускалась ни разу**, хотя рассчитана именно на него.
> GNOME, Sway и Hyprland написаны, но не запускались. В X11 любая программа может
> видеть нажатия через сам X-сервер, поэтому защита от кейлоггеров там не работает.

Это только демон с командами в терминале: окна настроек, трея, IBus и «исправления
выделенного» нет.

## Что проверено, а что нет

| Что | Как проверено |
|---|---|
| Автоисправление, отмена, запоминание слова | в обычной работе, X11, KDE |
| Правила детектора | юнит-тесты на настоящих словарях |
| Политика: пароль, терминал, неизвестный фокус | юнит-тесты с заглушками |
| Поле пароля в `zenity --password` (GTK 4) | вживую: распознаётся по подписи в окне |
| Поле пароля в `kdialog --password` (Qt) | вживую: распознаётся |
| Обычные поля в этих же программах | вживую: ложного срабатывания нет |
| Браузеры, Electron, менеджеры паролей, окна polkit | **не проверено** |
| Wayland, GNOME, Sway, Hyprland | **не проверено** |
| Сборка, clippy, тесты, shellcheck | CI на Ubuntu 24.04 проходит; работу самого демона CI не проверяет |

## Поля паролей: насколько это надёжно

**Гарантии нет.** Демон знает о поле только то, что приложение сообщает at-spi.
На живых диалогах выяснилось: GTK 4 и KPasswordDialog не ставят роль `password text`,
метаданными такое поле от обычного не отличается, а GTK 4 ещё и отдаёт через at-spi
реальный символ, а не маску. Поэтому признаков несколько, и каждый неполон:

1. роль `password text`;
2. маскированный текст: символы есть, а текст пуст или из точек (Qt). Проверяется и
   прямо перед каждым автоисправлением;
3. слова «пароль», «password», «passphrase» и т. п. в подписи поля или окна. **Это
   эвристика:** поле пароля без такой подписи в GTK 4 не будет распознано, а поле
   логина рядом с подписью «Пароль» будет считаться паролем.

Дополнительные меры по умолчанию:

- если фокус неизвестен, автоисправление выключено (`unknown_focus = "skip"`);
- в терминалах только ручное исправление: at-spi не видит запрос пароля `sudo`/`ssh`;
- в менеджерах паролей, pinentry и окнах polkit (по имени программы) демон не делает
  ничего, нажатия не попадают в буфер.

Если исправление всё же сработало в поле пароля, введённое изменится и вход не
пройдёт. Программы с паролями добавляйте в `sensitive_apps`.

## Модель угроз

**Защищает от:**
- попадания текста в журнал: там нет слов и их длин (без `-v`);
- рассылки текста по D-Bus: сигнала с текстом нет, в setgid-установке текст по D-Bus
  не отправляется вовсе;
- чтения клавиатуры обычными программами в Wayland (setgid вместо `uaccess` и группы
  `input`);
- чтения памяти демона другими процессами пользователя (`PR_SET_DUMPABLE=0`);
- попадания выученных слов на диск открытым текстом.

**Не защищает от вредоносной программы, работающей под вашим пользователем:**
- она может запустить setgid-бинарник с подставной шиной D-Bus и подделать at-spi.
  Текст она так не получит, но узнает время нажатий и факт исправлений, а её ложные
  ответы могут заставить демон исправлять в поле пароля. Запустить демон «только
  доверенным способом» в этой схеме нельзя;
- хеши выученных слов и их ключ лежат рядом, и такая программа прочитает оба. Слова
  из словаря подбираются перебором;
- полностью разделить права могла бы только отдельная системная служба.

**Память:** основной буфер закреплён в ОЗУ и затирается при сбросе, вся куча Rust
затирается при освобождении. Не покрыты стек, ещё не освобождённые блоки (например,
внутренний буфер evdev и очередь событий) и память ядра. В swap могут попасть всё,
кроме основного буфера. Отдельно: в проверенном диалоге GTK 4 первый символ поля
пароля читался через at-spi как есть; этот демон на такое повлиять не может.

## Отличия от WaySwitch

Сравнение составлено **по чтению кода WaySwitch, а не по тестам**, и это не оценка
проекта в целом: у него есть GUI и более широкая поддержка окружений.

| WaySwitch | wayswitch-rs |
|---|---|
| Правило udev: `uaccess` на клавиатуры | setgid `input`, права только на время `open()` |
| Опрос фокуса раз в 1,5 с | События at-spi плюс опрос |
| Устаревший снимок фокуса не запрещает исправление | Неизвестный фокус запрещает автоисправление |
| Поле пароля — по роли `password text` | Ещё маска и подписи (см. выше) |
| Узлы оболочки пропускаются при поиске фокуса | Событие из оболочки учитывается (окна polkit не проверены) |
| Отладочный журнал содержит слова вне распознанных полей пароля | Только длины, и только с `-v` |
| Сигнал `Corrected` с текстом, кроме распознанных полей пароля | Сигнала нет |
| `exceptions.txt` с выученными словами открытым текстом | HMAC-хеши; свой `exceptions.txt` только для ваших слов |

## Установка

Нужны Rust ≥ 1.82, dev-пакет `libxkbcommon` и группа `input` в системе. Служба
рассчитана на `systemd --user`.

```bash
./packaging/install.sh
```

Скрипт ставит `/usr/local/bin/wayswitch-rs` с правами `root:input 2755`, правило udev
для `/dev/uinput` и службу, а в GNOME ещё и расширение из оригинала. Если вы в группе
`input`, выйдите из неё, иначе смысла в защите нет. Удаление:

```bash
./packaging/uninstall.sh
```

Оригинальный WaySwitch ставить одновременно нельзя: они используют одно имя на шине.

## Использование

```bash
wayswitch-rs doctor
```

```bash
wayswitch-rs focus-test
```

`doctor` проверяет систему и безопасность, `focus-test` 20 секунд показывает, что
at-spi видит в поле. Проверьте им приложения, где вводите пароли. Остальные команды:
`status`, `pause`, `resume`, `fix-word`, `fix-phrase`, `reload`, `forget-learned`.
Ключи `run -v` и `run --dry-run` работают только вне setgid-установки.

Настройки: `~/.config/wayswitch-rs/config.toml`, пример в
`packaging/config.example.toml`. Рядом можно положить `exceptions.txt` (слова) и
`apps.txt` (программы).

Chromium, Electron и Qt показывают поля at-spi только при включённой доступности,
иначе автоисправление там выключено, а двойной Shift работает:

```bash
gsettings set org.gnome.desktop.interface toolkit-accessibility true
```

Для Qt ещё нужна переменная `QT_LINUX_ACCESSIBILITY_ALWAYS_ON=1`, например в
`~/.config/environment.d/`.
